## 4. 数据库迁移（设备侧，`S6.G` = PASS）

细节见 `03_BUSINESS_FLOW_EVIDENCE.md` 的 G 段。这里只记与"设备"有关的两条实操坑：

1. **只拉 `.sqlite` 会丢数据**：WAL 里的行不在主文件里。第一次拉出来 `focus_records` 只有 6 行，实际是 10 行。必须连 `-wal`、`-shm` 一起拉，并让 SQLite 重放。
2. **把文件写回应用私有目录**：`run-as … cp /sdcard/…` 会被拒（应用 uid 读不了 `/sdcard`）；`run-as … sh -c 'cat > …'` 也会被拒（重定向由外层 shell 建立）。可行路径是 `adb push` 到 `/data/local/tmp/` 再 `run-as … cp`。另外**不要用 `dd` 从 stdin 灌**——它把 176128 字节截成了 100341 字节（二进制经 adb shell stdin 会被翻译）。最终判据是**推回去的 sha256 与源一致**。

## 5. 输入与观测的盲区（写给下一个人）

| 现象 | 说明 |
|---|---|
| `adb shell input tap` 有时不生效，MCP 的 `android_ui_tap` 生效 | 两条输入路径盲区不同；改尺寸后坐标会重排，**每次点之前先重新取 bounds** |
| 无障碍树**只报可见节点** | 折叠线以下的东西不在树里。本轮因此差点报出一个假缺陷（"记录空态缺 CTA"，滚动后按钮就在） |
| 无障碍树的**顺序不等于布局** | 本轮据此差点报出"图鉴是单列列表"，截图一看就是四列网格 |
| 截图**不是**状态判据 | "装上没有"看 `installed_packs.json` 与目录；"记到哪个任务"看 `task_id`；"暂停是否计费"看 382−88=300 |
| 冷启动后过早读树 | 有一次启动后 9 秒读到的树是旧的（那一帧的伙伴节点仍是被修的旧形态），22 秒后同一屏干净。**关键结论要读两次** |
| 键盘会盖住底部按钮 | 新建任务页 `保存任务` 在键盘弹出时点不到，先 `KEYCODE_BACK` 收键盘 |
| **收键盘会让底部浮层移位，旧坐标会点到遮罩上** | 分心浮层（`记一下`）的输入框是 autofocus：一打开就弹键盘，`Padding(bottom: viewInsets)` 把整张浮层顶到屏幕中段（保存键在 y≈1344）。按 BACK 收键盘后浮层落回底部（保存键在 y≈**2164**）。**沿用弹键盘时取的坐标，会点到遮罩上，浮层被关掉、什么都没保存**——我因此连续两次以为"记一下静默丢数据"，第三次改用**收键盘后重新取的坐标**，一次成功，库里立刻多出 `('hello', None, 'open')`。**改尺寸或改键盘状态后必须重新取 bounds。** |

## 6. 性能（`S5.04`：启动与内存 PASS，帧时间 NOT_VERIFIED）

测的是 **profile 构建**（`flutter build apk --profile`，51.2 MB），装在同一个模拟器上。**绝对数字不代表真机**——这个 AVD 走 swiftshader 软件光栅、且是 profile 而非 release。有意义的是**稳定性与形状**：多次测量散不散、重复同样的操作内存会不会一直涨。

### 启动（`am start -W` 的 `TotalTime`）

| 项 | 五次 / 三次测量 | 结论 |
|---|---|---|
| 冷启动（`force-stop` 后） | 1465 / 1398 / 1480 / 1369 / 1420 ms | **≈1.4 s，极差 111 ms（8%）** |
| 暖启动（HOME 后回前台） | 97 / 91 / 96 ms | **≈95 ms** |

前两次冷启动是 6355 ms 与 3407 ms，之后稳定在 1.4 s 上下——那两次是 VM 预热与页缓存还没热，**不是稳态**，所以报 1.4 s 而不是报首次的那个数。

### 内存（`dumpsys meminfo` 的 TOTAL PSS）

| 时点 | TOTAL PSS | Native Heap | Java Heap |
|---|---|---|---|
| 刚启动、未操作 | 131.1 MB | 40.2 MB | 8.4 MB |
| 走完六个页面 + 一次完整专注（起 → 结束 → 保存） | 160.9 MB | 55.0 MB | 10.3 MB |
| 再走**同一个**循环一遍 | 154.6 MB | 47.4 MB | 10.3 MB |
| 再走第三遍 | 153.6 MB | 47.4 MB | 10.3 MB |

**判据是"重复同样的操作会不会一直涨"**：第二、三遍分别是 154.6 与 153.6 MB，**没有继续增长**（还略降），Native Heap 也从 55.0 回落到 47.4 并停住，Java Heap 三遍都是 10.27 MB。所以第一遍的 +30 MB 是**图片解码缓存 + GC 落定**，不是泄漏。**三轮同循环未发现无界增长。**

### 帧时间：`NOT_VERIFIED`，并说清为什么

`dumpsys gfxinfo` 对这个 App **是错的仪器**：它报 `Total frames rendered: 1`，因为它数的是 Android 平台视图的帧，而 Flutter 自己在 SurfaceView 上合成，帧不经过平台视图系统。拿它报"Janky frames 100%"会是**假结论**。

要测 Flutter 的帧时间得用 `flutter run --profile` 挂 DevTools 的 timeline（或 `SurfaceFlinger --latency`）。**这一项没做**，而且即便做了，swiftshader 软件光栅下的帧时间也不代表真机。所以：**帧时间与卡顿 `NOT_VERIFIED`，原因是仪器不对 + 环境不代表真机**，不是"测过了没问题"。
