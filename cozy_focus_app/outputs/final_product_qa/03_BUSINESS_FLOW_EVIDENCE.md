## C 首页 → 放松一下 → 开始休息 → 计时中 → 结束休息 → 存 RestSession → 时间线 → 重启仍在

**状态：PASS**

| 步骤 | 设备证据 |
|---|---|
| 首页 → 放松一下 | 树里 `放松一下，累了就休息一会儿吧`（在折线以下，先滚动） |
| 选 5 分钟 | 该 chip `clickable=true`——**这正是缺陷 21 的回归点** |
| 开始休息 | 运行中读作 `还剩 N 分钟`，**只说一遍**（缺陷 20 的回归点） |
| 结束休息 | 回到选择页 |
| 存 RestSession | SQLite `rest_sessions` 一行：`planned_seconds=300`、`start_at`→`end_at` 差 128 秒、`status='cancelled'` |
| 时间线 | `记录 → 今日 → 今日计划 → 时间线` 读到 `15:43 休息一下 2 分钟 · 提前结束`，与库里的 128 秒一致（2 分钟是 floor） |
| 重启 | `am force-stop` + 重启后时间线仍读到同一条 |

**这条流程找到的真实缺陷**：20（休息页把每个时长念两遍）、21（修 20 的那个改法把 25 处的"能按"一起改没了）。两条都在本流程内回归。

## D 专注 → 后台 → 恢复 → 暂停 → 继续 → 完成 → 保存 → 重启

**状态：PASS**

| 步骤 | 设备证据 |
|---|---|
| 开始专注（5 分钟） | 运行页 `专注计时 04:47，当前专注中` |
| 后台 45 秒 | `KEYCODE_HOME`，前台换成别的 App |
| 回前台 | 覆盖层 `已恢复专注状态` / `已恢复时长 1 分钟` / `本次专注 05:00` / `目标 05:00` |
| 恢复专注 | 继续到 `01:41` |
| 暂停 | `已暂停`，`专注计时 01:54，当前已暂停`；**等 18 秒后仍是 01:54**（暂停真的冻结） |
| 继续 | 回到 `01:41` 起继续走 |
| 完成 | 倒计时走完 → `专注完成`，`本次专注时长 05:00`，`+10 专注币` / `+25 Mochi XP` |
| 保存 | 填 note 后 `完成并返回首页`；SQLite `focus_records` 一行：`duration_seconds=300`、`note='device-walk-flowD'` |
| 重启 | `记录` 页 `今日记录 共 3 次`，含新那条 `16:09 – 16:15` |

**口径核对**：墙钟 382 秒 − 暂停 82 秒 = **记录 300 秒**。暂停不计入专注时间。

**这条流程找到的真实缺陷**：23（设计 03B 的"已恢复时长"卡片少了一行时间区间，实机左栏一行、右栏两行）。

## G 旧 Drift 库 → 迁移 → 数据完整性

**状态：PASS**

夹具是**设备自己产出的那个数据库**，不是手写的旧 schema：

1. 把 `cozy_focus.sqlite` 连同 `-wal`、`-shm` 一起拉出来，先让 SQLite 重放 WAL（**只读 `.sqlite` 会丢掉 WAL 里所有行**——第一次就丢了 4 条）。
2. `DROP TABLE rest_sessions, app_settings`（v9 之后新增的两张表），`PRAGMA user_version = 9`，`VACUUM` 折成一个文件。
3. 推回设备，确认**字节一致**（sha256 比对）、`user_version=9`、17 张表、`focus_records` 10 行。
4. 启动 App。

| 判据 | 迁移前 | 迁移后 |
|---|---|---|
| `PRAGMA user_version` | 9 | **11** |
| 表数 | 17 | **19**（新增 `rest_sessions`、`app_settings`） |
| `focus_records` | 10 | **10** |
| `focus_sessions` | 10 | **10** |
| `tasks` | 5 | **5** |
| `pets` | 1 | **1** |
| `craft_recipes` | 8 | **8** |
| `pet_memories` | 7 | **7** |
| `reward_ledger` | 10 | **10** |

界面复核：`记录` 页读到迁移过来的历史（`今日记录 共 4 次`，含 `16:25 – 16:30`、`16:09 – 16:15`）。

**这条流程找到的真实缺陷**：无。迁移链是对的——**这也是一条结论**，写下来是因为"没找到缺陷"和"没走"必须能分开读。

## 六条流程共同的读法

- **"页面在"不等于"流程通"**：C/D/E/F/H 五条各自找到的缺陷，没有一条能被"确认页面存在"发现——20 是朗读、21 是按下、23 是一行字、24 是两个存储的契约不一致、26 是换渲染器、27 是另一处写死的名字、29 是一行写死的参数。
- **判据尽量落在文件系统**：E 的"装上没有"看 `installed_packs.json` 与目录；G 的"没丢"看行数；H 的"记到哪个任务"看 `task_id`；D 的"暂停不计费"看 382−82=300。
- **两次差点报假缺陷**（写进 `01_VISUAL_MATRIX.md` 的方法教训）：从无障碍树顺序推断布局、以及没滚到就断言"缺按钮"。
